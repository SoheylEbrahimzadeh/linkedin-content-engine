Privacy Policy — LinkedIn Content Engine

Last updated: 2 October 2026

1. What this application is

LinkedIn Content Engine is a personal, open-source tool (source code) operated by a single owner, GitHub user SoheylEbrahimzadeh, to plan, review and publish posts on the owner's own LinkedIn member profile. It is not offered to other users, does not create accounts for anyone, and does not access other members' data.

2. LinkedIn data the application uses

  • OAuth access token. The owner creates a LinkedIn access token with the scopes openid, profile and w_member_social. The token is used only to call LinkedIn's official APIs on the owner's behalf. No refresh token is used. The token is stored only as an encrypted Cloudflare Worker secret (or, when publishing from the owner's computer, in the macOS Keychain). It is never written to the database, to logs, to source code or to any API response.
  • Profile identifier. To publish as the owner, the application reads the OpenID Connect /v2/userinfo endpoint to obtain the owner's member identifier and derives the person URN (urn:li:person:…). The URN is stored in the application's configuration. The owner's health checks repeat this read-only call to confirm the token still works and still belongs to the configured member. Only the identifier is used: the name and picture returned by that endpoint are not stored, and the cloud service does not pass them on at all.
  • Posts. The application sends the text of a post the owner has explicitly approved to LinkedIn's Posts API, and records LinkedIn's response: the post identifier (URN), its URL when available, the time and the outcome.
  • Images. If an approved post has an image, the image file the owner approved is uploaded through LinkedIn's Images API and referenced in the post.

The application does not read the owner's feed, connections, messages, other members' profiles or posts, and does not use LinkedIn data for advertising, profiling or any purpose other than publishing the owner's own approved posts. Engagement figures, if recorded at all, are entered by the owner manually.

3. Where data is processed and stored

  • Cloudflare Workers and D1 (this site). The Worker stores, in a Cloudflare D1 database: scheduling settings (time zone, cadence, LinkedIn API version, person URN, token expiry date, the publish switch), posts the owner approved and scheduled (text, approved image up to 1.5 MB, alt text, content hashes), scheduling consents, publication records, an audit log of actions with the identity of the person or service that performed them, and a read-only copy of the owner's planning dashboard (drafts, research notes with sources, calendar and quality checks).
  • Cloudflare Access protects the dashboard and API: only the owner (and an automated service credential of the owner) can use them. Cloudflare Access sets its own authentication cookie for signed-in sessions; this application sets no cookies and uses no analytics or tracking.
  • GitHub. The owner's private GitHub repository holds the owner's own planning data, and GitHub Actions in that repository update the dashboard copy and run read-only health checks through Cloudflare Access. The public repository contains source code and fictional example data only.
  • LinkedIn receives the approved posts and images described above.

No data is sold or shared with anyone else.

4. Human approval and safety

Nothing is published automatically because a draft was generated or a schedule fired. Every post must be approved by the owner against the exact approved text (and image); the cloud publisher only publishes a post the owner explicitly scheduled, only while the owner's publish switch is on, and refuses if the text or image changed after approval.

5. Retention and deletion

  • Scheduling records, publication records and the audit log are kept in D1 until the owner deletes them. The dashboard copy is a single record that is replaced on every update.
  • The LinkedIn access token expires after LinkedIn's validity period (60 days) and is not renewed automatically. The owner can revoke the application's access at any time in LinkedIn's Settings → Data privacy → Permitted services, and can delete the Worker secret and the D1 data in Cloudflare.
  • Posts already published on LinkedIn are governed by LinkedIn's own policies and can be deleted on LinkedIn.

6. Security

All traffic uses HTTPS. The dashboard and API refuse every request that does not carry a valid Cloudflare Access identity (fail-closed). Credentials are kept only in encrypted secret stores, never in the database or source code, and the source repository is scanned for secrets on every change.
